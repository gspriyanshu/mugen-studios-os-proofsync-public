# Jaipur dental simulation public-release boundary

Approved public surface:

- one indexable MUGEN portfolio case study;
- one indexable, nonclinical dental-website trust checklist;
- ten patient-facing interface-simulation routes marked `noindex,follow` and excluded from the XML sitemap;
- one local CSS file with no remote asset dependency;
- one negative-fixture validator.

The patient layer is a fictional Jaipur interface. It does not represent an operating clinic, a practitioner, a Google Business Profile, patient information, a contact channel or an appointment workflow. MUGEN Studios OS is the only Organization entity in patient-page structured data. No clinical review is represented.

The case study and checklist may discuss SEO, AEO, GEO, local implementation, authority development and measurement because they are owner-facing proof pages. They state that search eligibility is not indexation or ranking, and that prospects and drafts are not acquired editorial backlinks.

No protected workflow, verification file, tracking configuration or existing dental route may be weakened to admit this surface. The dedicated validator must reject visible delivery-method jargon on patient routes, fake local data, invented practitioners, active booking/contact actions, forbidden schema, patient indexability, patient sitemap inclusion, patient-data fields, network/storage access and fabricated outcomes.
