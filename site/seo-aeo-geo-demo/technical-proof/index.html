NESTRA Technical SEO Evidence

This audit separates source observations, implemented demonstration controls, and post-release measurements. It turns findings into acceptance criteria that an engineer can ship and a reviewer can test against the released artifact.

Evidence boundary: source inspection supports the findings below. The routes are index-eligible, internally connected, and project-sitemap-listed; external discovery and indexation remain pending. No source observation is presented as a Core Web Vitals result, ranking change, or traffic outcome. The source-inventory method and retained facts are recorded in the public-safe source inventory and release record.

Prioritized audit

Fix eligibility and interpretation before chasing visibility.

  1. Metadata and canonicalSource lacked a description, canonical, and social URL. The demonstration supplies one exact URL per page and checks parity.
  2. Crawlable internal pathsSource contained no crawlable links. The evidence set now connects all five pages with ordinary anchors and no script dependency.
  3. Indexing directiveThe new routes use the exact authorized index/follow directive. The repository root remains unchanged and intentionally separate.
  4. Structured data truthSource had no JSON-LD. The demonstration allows only non-executable JSON-LD that matches visible page facts.
  5. Image deliveryTwenty-three referenced raster images totaled 37.61 MiB. Preserve descriptive alt text while creating responsive sizes and modern formats before image-heavy release.
  6. Measurement contractRecord discovery, indexing, impressions, clicks, queries, page performance, conversions, and AI visibility only when the relevant platform exposes data.
